# AGENTS.md - рабочий контекст проекта Topoliner

Файл читается первым в начале любого нового чата по проекту. Единственный
источник правды - этот файл и комплект документов рядом с ним, а не переписка.
Изменилось что-то в постановке или в процессе - правка идёт сюда.

Раздел «Требования к текстам» общий для трёх плагинов линейки. При правке
в одном месте он правится и в остальных.

## С чего начинается сессия

1. Прочитать этот файл целиком.
2. Прочитать те документы комплекта, которых касается задача.
3. Сверить номер версии в рабочей копии и в установленном плагине.
4. Назвать задачу и признак готовности до того, как что-то менять.

Переписка прошлых сессий не восстанавливается и источником не считается. Если
в ней было решение, которого нет здесь, оно записывается сюда, а потом
используется.

## Что это

Плагин QGIS для топологии полигональных и линейных покрытий. Основная работа
идёт в Processing. Кнопка на панели инструментов есть у одной врезки контура,
её применяют в режиме редактирования. Текущая версия 0.13.0,
`experimental=False`. Код рабочий и опубликован.

Инструменты находят нарушения и отделяют технический мусор от возможного
смысла. Мусор исправляется в новый слой. Отдельно идут сшивка границ, вставка
узлов, контроль сборки по атрибуту, врезка контура с общей кромкой разреза,
упрощение покрытия без разрыва общих границ и разбор покрытия на узлы и дуги.

Исходный слой не изменяется никогда. Автоматика не выбирает, чья граница
верна, она смотрит только на масштаб расхождения.

Место в линейке. Isoliner строит контуры, Topoliner приводит их в порядок,
Isoliner3D считает объём. Общего кода с ними нет, только соседство по задаче.
Лицензия GPL 3, у двух соседних плагинов GPL 2 или новее.

## Среда выполнения

- **QGIS 3.16 и новее, включая QGIS 4.** В `metadata.txt` стоят границы 3.16
  и 4.99. Проверено на 4.0.3. Отдельной сборки под каждую линию нет, код общий.
- **Python из состава QGIS.** На рабочей машине это
  `C:\Program Files\QGIS 4.0.3\apps\Python312\python.exe`. Переменная
  `sys.executable` внутри QGIS указывает на `qgis-bin.exe` и для запуска
  скриптов не годится.
- **Зависимостей за пределами QGIS нет.** Геометрические операции идут через
  GEOS, в бою через QGIS, в тестах через Shapely.
- **Тесты.** unittest, 9 файлов в `topoliner/tests`, QGIS не требуется.
  Непрерывная сборка гоняет их на Python 3.9 и 3.12.

## Устройство

Геометрическое ядро отделено от QGIS и работает со списками координат.
Это `topo_core`, `topo_checks`, `line_checks`, `topo_simplify`, `boundaries`,
`coverage`, `cut` и `z_restore`. Рядом лежат два модуля без геометрии,
`rounding` для округления величин и `field_aliases` для подписей полей. Диалоги Processing лежат отдельно, в `audit_algorithms`,
`line_algorithms`, `topo_algorithm` и `simplify_algorithm`.

Операции пересечения идут через адаптер `geom_backend`. В бою за ним QGIS,
в тестах Shapely, под обоими один GEOS.

Модуль `plugin.py` регистрирует провайдер `topoliner` и три кнопки. Алгоритмы
наследуют `QgsProcessingAlgorithm` напрямую, общего базового класса нет.

Кнопка врезки собрана из трёх модулей. `cut_tool` рисует контур по карте
и держит настройки, `cut_edit` пишет результат в буфер редактирования слоя,
`ui_dialogs` рисует два окна. Имена Qt берутся через `qt_compat`: в Qt 6
перечисления стали областными, а плагин работает и в QGIS 3.16 с Qt 5.

Импорты ядра пишутся под оба контекста.

```python
try:  # внутри плагина QGIS
    from .topo_core import clean_topology
except ImportError:  # headless-тесты
    from topo_core import clean_topology
```

## Решения, которые не пересматривать без обсуждения

Раздел удерживает договорённости, к которым разговор возвращается чаще всего.
Каждое решение записано тезисом в первой фразе, дальше основание.

**Два порога задают всё поведение.** Это допуск в единицах длины и порог
площади. Всё, что мельче, исправляется молча. Всё, что крупнее, попадает
в слой оставшихся проблем с пояснением и не изменяется ни при каких
настройках.

**Метка severity делит находки на auto и review.** Смешивать разряды нельзя.
Широкие перекрытия не вычитаются, крупные щели не заполняются, дубликаты
и вложенные объекты не разрешаются. Это не недоработка, а условие продукта.
Автоматика не располагает сведениями о том, чья граница верна.

**Исходный слой не пишется.** Результат идёт в новый слой. Объекты
не удаляются без отдельного разрешения в диалоге.

**Вершина не смещается дальше допуска.** Слияние жадное по лидеру. Лидер
кластера не двигается, поэтому цепочек сноса не возникает.

**Вставка узлов не меняет ни форму, ни площадь.** Узел ставится в проекцию
точки на ребро, то есть строго на прямую этого ребра.

**Правка, отнимающая у объекта больше четверти площади, отменяется.** Объект
возвращается в исходный вид.

**Объект уже допуска не изменяется.** При слиянии его противоположные берега
слиплись бы. Такой объект остаётся опорой для соседей.

**Повторный запуск по результату ничего не меняет.** Единственное исключение -
упрощение со сглаживанием, где каждый проход срезает углы заново. Оба
поведения закреплены тестами в `tests/test_topo_simplify.py`.

**Кромка разреза приходит из одного наложения.** Контур собирается в одну
геометрию, и все вычитания и пересечения делаются против неё. Кромка достаётся
обеим сторонам одинаковой. Отдельная чистка каждой стороны возвращает
расхождение вершин, ради которого инструмент и сделан. Закреплено тестами
в `tests/test_cut.py` через модель покрытия.

**Новый объект наследует атрибуты доноров при совпадении.** Поле, у которого
все отдавшие площадь соседи имеют одно значение, получает это значение. Поле
с разными значениями остаётся пустым. Ключ слоя не переносится никогда.

**Общая граница прореживается один раз.** Покрытие режется на дуги, дуга
прореживается однократно, концы дуг неподвижны. Обоим соседям достаётся один
и тот же результат.

**Величины округляются до значащих цифр, а не до знаков после запятой.**
Четыре значащие цифры. Фиксированное количество знаков одинаково плохо работает
на разных масштабах, площадь в микроны при четырёх знаках превращается в ноль.
Количества не округляются вовсе, потому что в поле value наряду с площадью
и смещением попадает количество объектов. Делает это модуль `rounding`.

**У каждого поля выходного слоя есть псевдоним на языке интерфейса.** Имена
полей остаются латинскими, по ним пишут выражения. Псевдоним ставится слою
после загрузки, обработчиком завершения. Псевдоним на поле приёмника QGIS
встречает предупреждением о несовместимости с временными слоями. Подписи лежат
в модуле `field_aliases`, установка в `qgis_helpers`.

**Результат в GeoPackage несёт подписи внутри файла.** Второе имя поля пишется
через `AlterFieldDefn` после прогона, в `postProcessAlgorithm`, когда приёмник
уже закрыл файл. Так слой показывает подписи в чужом проекте. Обращение к GDAL
идёт с погашенными предупреждениями Python, иначе предупреждение библиотеки
роняет QGIS. Остальные форматы второго имени поля не хранят.

**Ядро не знает про QGIS.** Всё, что обращается к API QGIS, лежит в диалогах
и в адаптере. Перенос вычислений в диалог ломает тесты, которые идут без QGIS.

## Чего нельзя делать в коде

**Порождать предупреждения Python в коде, который выполняется в потоке
Processing.** Обработчик предупреждений QGIS собирает стек вызовов и роняет
программу с нарушением доступа. Так уже случалось дважды, на
`parameterAsFields` и на `locale.getdefaultlocale`. Любой устаревший вызов
в рабочем потоке несёт этот риск.

**Оставлять `except Exception`.** Ловится конкретное исключение. Тест
в `tests/test_i18n.py` следит за этим, а также за обработчиками из одного
`pass`, `continue` или `break`.

**Писать абсолютные пороги там, где величина зависит от масштаба.** Проверка
на параллельность рёбер была абсолютной и при координатах в миллионы метров
не срабатывала вовсе. Сравниваются относительные величины, синус угла,
а не определитель.

**Оставлять строку без перевода.** Всё, что видит человек, идёт через `tr()`.
Тест требует наличия русской и английской версии.

## Работа через мост к QGIS

Мост выполняет Python внутри QGIS пользователя и даёт доступ к его файловой
системе. Отдельный доступ к дискам и к Dropbox для этого не нужен.

- **Долгие задачи через мост не идут.** Код исполняется в главном потоке QGIS.
  Полный прогон тестов подвешивает интерфейс и обрывает вызов. Такие задачи
  запускаются через `subprocess` с ограничением по времени.
- **Большие файлы через мост не передаются.** Применяются точечные замены
  строк с проверкой `sha256` после каждой. Производные файлы пересобираются
  скриптами репозитория на рабочей машине.
- **Запись только в двоичном режиме.** Текстовый режим на Windows превращает
  перевод строки в CRLF, и контрольная сумма расходится. Используется
  `open(path, "wb")` с явным переводом строки.
- **Перед правкой рабочего каталога делается резервная копия.** Открытый
  в QGIS проект не трогается.

## Что решает автор, а не помощник

Список снимает повторный разбор одних и тех же вопросов.

- номер версии и момент выпуска
- состав инструментов панели и их нумерация
- публикация в каталогах, на GitHub и в группах
- содержание объявлений о выпуске
- величины умолчаний, которые видит пользователь
- границы задачи, если постановка пришла от стороннего пользователя

## Что не делается без спроса

Действия, которые нельзя отменить или которые видит третья сторона.

- коммит и отправка в хранилище версий
- выкладывание архивов в обменную папку
- публикация выпуска и объявления
- удаление файлов рабочей копии и перезапись чужих правок
- изменение открытого в QGIS проекта пользователя
- установка и обновление плагина в его QGIS

Готовность к такому действию сообщается, само действие ждёт ответа.

## Приёмка работы

Задача имеет признак готовности, который можно проверить. Признак называется
до начала работы, а не после.

Для правки ошибки сначала пишется воспроизведение. Сказано, на каких данных
ошибка видна и что именно неверно. Если воспроизвести не удалось, так
и говорится, а догадка о причине не выдаётся за причину.

Для новой части работы называются способ запуска и ожидаемый результат, потом
делается сама работа.

Работа из нескольких шагов получает короткий план с проверкой на каждом шаге.

«Готово» говорится только после прогона. Если прогона не было, говорится
«сделано, не проверялось, нужен прогон на вашей стороне». «Должно работать»
результатом не считается.

Разобранная ошибка получает сторожа, то есть проверку, которая краснеет
на прежнем поведении. Сторож проверяется подменой на старое поведение, иначе
неизвестно, ловит ли он что-нибудь.

## Номера версий

Номер стоит в `topoliner/metadata.txt` в поле `version` и повторяется
в `CHANGELOG.md`, в обоих README и в именах архивов. Это один номер,
расхождение недопустимо.

Перед каждой выдачей машинно проверяется, что во всех файлах стоит одна
версия. Проверка на глаз не засчитывается.

Номер меняется в момент выдачи, а не в момент правки. Выданный номер закрыт,
и следующая правка идёт под новым.

Архивы собираются одним прогоном `tools/build_zip.py`. Архив для каталога
и архив для хранилища версий берутся из одной сборки.

## Проверки перед выпуском

```
python tools/preflight.py     готовность к каталогу
python tools/check_docs.py    согласованность документации
python tools/build_zip.py     сборка архивов
cd topoliner && python -m unittest discover -s tests
```

Тесты идут без QGIS. Прогон в самом QGIS обязателен для всего, что касается
диалогов, окон и рабочих потоков. Проверяется, что панель показывает все
одиннадцать инструментов, что кнопки врезки работают в режиме редактирования
и что в журнале сообщений нет предупреждений Python.

## Сборка документов

Единственный источник - markdown. Схемы в `doc/figures` рисуются скриптом
`tools/make_figures.py` на двух языках. Руководства собираются
`tools/build_manual.py`, готовые PDF кладутся внутрь плагина, в `topoliner/doc`.
Страница проекта собирается `tools/build_site.py`.

Сборка PDF идёт в два шага. Pandoc превращает markdown в самодостаточную
страницу HTML со встроенными картинками и оглавлением, браузер печатает эту
страницу в PDF. TeX не нужен. Pandoc берётся из PATH либо из пакета
`pypandoc_binary`, который ставится без прав администратора командой
`python -m pip install --user pypandoc_binary`. Печатает Edge или Chrome
в безоконном режиме. Оформление задано таблицей стилей внутри
`tools/build_manual.py`.

Таблица инструментов в README и в руководстве должна совпадать с провайдером.
При добавлении инструмента правятся оба README, оба руководства, справка
в `help_texts` и подсказки полей.

## Требования к текстам

Общая часть действует всегда, дальше уточнения по типам текстов.

### Общее

**Пунктуация.** Тире в прозе только в виде ` - `, длинного тире нет. Точки
с запятой нет, вместо неё отдельное предложение или запятая с союзом.
Двоеточие стоит перед списком, в соотношениях, в адресах и в названиях.
Внутри предложения двоеточия нет, там работают запятая, точка или тире. Знак
минус в формулах пишется дефисом, а не математическим минусом.

**Предложение.** Короткое. Длинные сложносочинённые предложения разбиваются.
Предложение полное, с подлежащим и сказуемым. Назывных обрывков нет.
Ориентир - средняя длина около 10 слов, предложений длиннее 28 слов единицы,
длиннее 34 нет.

**Абзац.** Открывается тезисом, дальше разворачивается. Каждый факт сказан
в одном месте, повтор заменяется ссылкой на это место.

**Стоп-слова.** «Честный», «честнее», «врать», «врёт» и производные, «главные
грабли», «софт», «кучка», «гладь», «скучный», «лаг», «членение»,
«наблюдённый».

**Разговорная лексика недопустима.** Бытовых и медицинских сравнений нет.
Запрещены «предъявить», «соблазн», «лесенка», «сходит с рук», «деваться
некуда», «вперемешку», «крутить параметры», «руками» с заменой на «вручную»,
«кучу», «под рукой», «мелочь» и подобные.

**«Число» и «количество».** Где считаются штуки, пишется «количество».
«Число» остаётся в математическом смысле величины и в датах.

**Утверждение без сравнения и без оценки.** Что важнее и что лучше,
не говорится. Факты даются рядом, читатель сравнивает сам.

**Содержание.** Без воды, догадок и рассуждений вокруг темы. Термин
объясняется при первом употреблении. Утверждение либо проверяемо, либо его
нет.

### Голос

В текстах для пользователя первого лица нет. Работают безличные формулировки
вида «инструмент выдаёт», «слой не изменяется». Обращение на «вы» допустимо
там, где описывается действие пользователя.

От автора в публичных текстах - «мы», «создаём», «разрабатываем».

### Подсказки полей

Подсказка объясняет, что делает величина и чем оборачивается её изменение.
Диапазоны и умолчания повторять не нужно, их показывает сам диалог.

Длина - от одного до пяти предложений. Разметки нет, перевод строки задаётся
в самом тексте.

Подсказка есть у каждого параметра. Параметр без подсказки считается
незавершённым.

### Справки инструментов

Справка открывается тем, что инструмент делает и что получается на выходе.
Дальше идут разделы с заголовками в теге `b`, списки в тегах `ul` и `li`.

Заголовок справки совпадает с названием инструмента в панели.

Обещания справки совпадают с гарантиями из раздела решений. Формулировка
гарантии берётся оттуда дословно, а не пересказывается.

Ссылка на соседний инструмент даётся его номером в теге `b`.

### Заметки к выпуску и объявления

Пишутся для того, кто пользуется, а не для того, кто делал. Сначала то, что
человек увидит своими глазами, потом одной фразой зачем это ему.

Имён файлов и внутренних названий нет. Разбор причины и подробности работы
остаются в журнале изменений, на страницу выпуска они не идут.

Числа приводятся только те, что сопоставимы с работой читателя.

### Письма и сообщения от первого лица

Сдержанно и по делу. Эмоциональных заявлений нет. Похвалы словам собеседника
нет. Самокритики нет, пока её не попросили. Решение не описывается, пока оно
не сделано. Вопрос должен быть вопросом, а не вежливой формой утверждения.

## Проверка текстов

Выполняется после правки текстов и перед выпуском. Текст считается готовым
после прогона, а не после правки.

### Что проверяется

**Пунктуация и лексика.** Длинное тире, точка с запятой, двоеточие внутри
предложения, стоп-слова, разговорная лексика, «число» вместо «количества».
Проверка машинная, по всем подсказкам, справкам и файлам markdown.

**Длина предложений.** Средняя длина и количество предложений длиннее 28
и 34 слов измерены и названы числом.

**Расхождения между документами.** Состав инструментов в README, в руководстве
и в провайдере. Названия инструментов и номера. Перечень полей диалога против
таблицы в руководстве. Перечень выходных атрибутов против таблицы
в руководстве. Русская и английская версии одного документа.

**Термины.** Одна сущность называется одинаково везде. Отдельной проверки
требуют пары «допуск» и «отклонение», «щель» и «зазор», «полость» и «дыра»,
«узел» и «вершина», «дуга» и «ребро».

**Гарантии.** Формулировка гарантии в README, в руководстве, в справке
и в этом файле совпадает дословно. Оговорка про сглаживание стоит всюду, где
названа идемпотентность.

**Числовые значения.** Номер версии. Величины умолчаний. Числа из примеров
прогонов.

### Что не проверяется

Стиль, объём, порядок разделов.

### Формат ответа при внешней проверке

Перечень находок. По каждой указываются файл, раздел, цитата и суть
расхождения. Правки в текст не вносятся. При отсутствии находок так
и указывается.

## Когда данных не хватает

Недостающее называется недостающим. Текст не достраивается правдоподобными
значениями, и отсутствие ответа не заменяется догадкой.

Если для разбора нужен слой или проект, которого нет, он запрашивается
до начала работы, а не после сдачи. Ошибка, которую не на чем воспроизвести,
не объявляется ошибкой.

## Открытые вопросы

Полные перечни стоят в документах комплекта, здесь ключевые.

Отростки в полигонах после объединения средствами QGIS. Нужен
воспроизводимый образец. На исходном слое их нет, проверка дала 7 игл
и 0 дублей на 15 700 колец.

Обратная сборка полигонов из отредактированных дуг. Ядро это умеет, способ
связи отредактированного слоя дуг с исходным покрытием не выбран. Возможные
варианты - по `arc_id` или по геометрии.

Врезка буферизованных линий в покрытие. Сама врезка контура сделана, это
инструмент 1.08 и кнопка. Открытым остаётся построение буфера по полю ширины:
чем кончается буфер на концах линии и как быть с линией, идущей по существующей
границе. Постановка пришла от Андрея Пирогова, образца данных с полем ширины
пока нет.

## Журнал решённых вопросов

Раздел хранит вопросы, которые разбирались долго и могут всплыть снова.
Запись состоит из тезиса в заголовке, обстоятельств и принятого решения.

**Проверка на параллельность рёбер была абсолютной.** Условие сравнивало
определитель с величиной `1e-15`. При координатах в миллионы метров оно
не отсекало ничего. На кадастровом слое из 665 находок 663 оказались
границами, нарисованными дважды почти одинаково. Вставка узлов не сходилась
за 8 проходов и давала 609 941 узел. После перехода к относительной проверке
по синусу угла получилось 3 прохода и 1141 узел. Не возвращать абсолютное
сравнение.

**Предупреждения Python из потока Processing роняли QGIS.** Случалось дважды,
на `parameterAsFields` и на `locale.getdefaultlocale`. Обработчик
предупреждений QGIS собирает стек вызовов и завершает процесс с нарушением
доступа. Обход для первого лежит в `qgis_helpers.py`, для второго язык
берётся из переменных окружения напрямую. Не возвращать устаревшие вызовы
в рабочий поток.

**Потолок допуска считался по минимальной ширине кольца.** Одно волосяное
кольцо шириной в микроны давало совет 0.0000038 вместо 8.12 метра. Потолок
считается по пятому процентилю. Не возвращать минимум.

**Выданы архивы из разных сборок.** Один архив содержал 0.12.2, другой
0.12.3. Удаление старых файлов вернуло ошибку ввода и вывода, которая была
пропущена. Введена машинная проверка совпадения версии во всех файлах перед
каждой выдачей. Не выдавать архивы без этой проверки.

**Идемпотентность сглаживания.** В README и в руководстве стояло
безоговорочное утверждение о том, что повторный запуск ничего не меняет.
Упрощение со сглаживанием сдвигает вершины на 1.15 при допуске 1. Оговорка
добавлена в оба README и в оба руководства, два теста закрепляют оба
поведения. Не снимать оговорку.

**Доступ к файлам пользователя идёт через мост к QGIS.** Отдельный доступ
к дискам и к Dropbox не нужен. Порядок и ограничения описаны в разделе
о работе через мост.
