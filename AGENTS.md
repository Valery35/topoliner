# Правила работы с Topoliner

Файл для того, кто правит этот репозиторий, включая ИИ-помощника.
Здесь только то, что нельзя нарушить, не сломав продукт.

## Что это за плагин

Набор инструментов Processing для полигональных и линейных покрытий.
Исходный слой не изменяется никогда, результат идёт в новый.

## Главное правило: два порога

Поведение задают допуск в единицах длины и порог площади. Всё, что мельче,
исправляется молча. Всё, что крупнее, попадает в отдельный слой с пояснением
и не трогается ни при каких настройках.

Нельзя чинить широкие перекрытия, заполнять крупные щели, разрешать дубликаты
и вложенные объекты. Это не недоработка, а контракт: автоматика не знает,
чья граница верна, и решение остаётся за человеком.

Метка severity делит находки на auto и review. Смешивать их нельзя.

## Гарантии ядра

- Вершина не смещается дальше допуска. Слияние жадное по лидеру: лидер
  не двигается, поэтому цепочек сноса не возникает.
- Вставка узлов не меняет ни форму, ни площадь вовсе. Узел ставится
  в проекцию точки на ребро.
- Правка, отнимающая у объекта больше четверти площади, отменяется, объект
  возвращается как был.
- Объект уже допуска не изменяется и служит опорой для соседей.
- Повторный запуск по результату ничего не меняет. Единственное исключение:
  упрощение со сглаживанием, там каждый проход срезает углы заново. Оба
  поведения закреплены тестами в tests/test_topo_simplify.py.
- Атрибуты сохраняются, объекты не удаляются без явного разрешения.

## Устройство

Геометрическое ядро отделено от QGIS и работает со списками координат:
topo_core, topo_checks, line_checks, topo_simplify, boundaries, coverage.
Операции пересечения идут через адаптер geom_backend: в бою QGIS, в тестах
Shapely, под ними один GEOS.

Диалоги Processing лежат отдельно: audit_algorithms, line_algorithms,
topo_algorithm, simplify_algorithm.

Импорты ядра пишутся под оба контекста:

    try:  # внутри плагина QGIS
        from .topo_core import clean_topology
    except ImportError:  # headless-тесты
        from topo_core import clean_topology

## Чего нельзя делать

**Порождать предупреждения Python в коде, который выполняется в потоке
Processing.** Обработчик предупреждений QGIS собирает стек вызовов и роняет
программу с нарушением доступа. Так уже случалось дважды: parameterAsFields
и locale.getdefaultlocale. Проверка: прогнать плагин с фильтром, где любое
предупреждение становится ошибкой.

**Оставлять except Exception.** Ловить нужно конкретное исключение. Тест
в tests/test_i18n.py следит за этим, как и за обработчиками из одного pass,
continue или break.

**Писать абсолютные пороги там, где величина зависит от масштаба.** Проверка
на параллельность рёбер была абсолютной и при координатах в миллионы метров
не срабатывала вовсе. Сравнивать надо относительные величины: синус угла,
а не определитель.

**Оставлять строку без перевода.** Всё, что видит человек, идёт через tr(),
и тест требует наличия обеих версий.

## Проверки перед выпуском

    python tools/preflight.py     готовность к каталогу
    python tools/check_docs.py    согласованность документации
    python tools/build_zip.py     сборка архивов
    cd topoliner && python -m unittest discover -s tests

Тесты идут без QGIS. Прогон в самом QGIS обязателен для всего, что касается
диалогов и потоков.

## Документация

README на двух языках, руководства в doc/, собранные PDF внутри плагина
в topoliner/doc. Таблица инструментов в README и в руководстве должна
совпадать с провайдером: при добавлении инструмента правятся оба README,
оба руководства и справка в help_texts.

Схемы в doc/figures рисуются скриптом tools/make_figures.py на двух языках,
руководства собираются tools/build_manual.py.
