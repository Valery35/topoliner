# Прогоны Topoliner для крейта rustgis-kit

Папка хранит эталонные прогоны 11 инструментов модуля QGIS. По ним
сверяется перенос расчётов на Rust. Формат прогонов задаёт крейт
rustgis-kit, раздел README «Граница между крейтом и продуктом».

| Файл | Содержание |
|---|---|
| `tool_runs.json` | 38 прогонов, вход, значения полей, выход, журнал |
| `../tools.json` | описание инструментов, его читает `Catalog::parse` крейта |

Оба файла собирает скрипт `tools/export_tools.py`. Вручную они не правятся.

## Как пересобрать

Скрипт работает только в Python из состава QGIS, с окружением QGIS.

```
"C:\Program Files\QGIS 4.2.3\bin\python-qgis.bat" tools/export_tools.py
"C:\Program Files\QGIS 4.2.3\bin\python-qgis.bat" tools/export_tools.py --check
```

Первая команда пишет оба файла. Вторая ничего не пишет. Она сравнивает
свежий прогон с файлами в репозитории и возвращает код 1, если хоть один
файл разошёлся. Номер версии плагина стоит в обоих файлах, поэтому смена
версии требует пересборки.

## Откуда берутся данные

Входы повторяют фигуры из тестов `topoliner/tests`. Это перекрытия,
щели, вершины у чужого ребра, недоводы и перелёты линий, сборка группы
по атрибуту, врезка контура, извилистая общая граница.

Выход получен настоящим прогоном алгоритма Processing в QGIS без окна,
а не вызовом ядра напрямую. В выход поэтому входит всё, что делает диалог
поверх ядра. Это округление величин, состав полей, порядок объектов,
пояснения в поле note и журнал.

Каждый случай прогоняется дважды, с русским и с английским интерфейсом.
Скрипт проверяет, что геометрия обоих прогонов совпадает. Строки в `values`
русские. Английские строки, которые отличаются, лежат в `values_en`
по имени поля.

## Прогон

| Поле | Содержание |
|---|---|
| `tool` | имя алгоритма, как `name` в `tools.json` |
| `case` | имя случая |
| `about` | что проверяет случай |
| `values` | значения всех полей, заданные и умолчания |
| `input` | объекты входных слоёв по ключу поля |
| `output` | выходные слои по ключу поля |
| `report` | журнал прогона, пары вида и строки |
| `tolerance` | допуск сверки координат и значений |

В `values` слой описан ключом `@КЛЮЧ` со сведениями о слое. Необязательный
выход стоит со значением `true`, обязательный выход в `values` не входит.

Координаты - метры системы `EPSG:32637`, высоты нет, вместо неё `null`.
Объект входа устроен как у крейта, это `id`, `attrs` и `parts`. Рядом
лежит `wkt`. Идентификатор `id` совпадает с номером объекта во временном
слое QGIS. На него ссылаются поля `fid_a`, `fid_b`, `left_fid`
и `right_fid` выхода.

## Выход

Выход устроен как у крейта. Поля идут списком пар имени и типа,
у объекта есть `values` по порядку полей и `geometry`.

| Геометрия | Вид |
|---|---|
| точка | `{"xyz": [x, y, z]}` |
| линия из одной части | `{"points": [[x, y, z]]}` |
| полигон и составная линия | `{"parts": [...], "wkt": "..."}` |

У крейта нет своего вида геометрии для полигона. Кольца лежат частями,
как на входе, по порядку - внешнее кольцо, потом дыры. Принадлежность
колец частям однозначно задаёт только `wkt`.

## Как сверять

Сравнивать нужно разобранную геометрию, а не строки WKT. Координаты
сравниваются с допуском из `tolerance`.

Порядок объектов в выходе тот же, что выдаёт модуль. Номер находки `num`
зависит от этого порядка.

Поле `value` округлено модулем `rounding` до четырёх значащих цифр.
Количества не округляются. Расхождение в последней значащей цифре говорит
о разнице в округлении, а не в геометрии.

Поле `fid_b` равно -1, если второго объекта у находки нет.

## Чего в прогонах нет

Перечень лежит в `skipped` файла прогонов, параметры без вида поля
у крейта лежат в `omitted` файла `tools.json`.

- текстовый отчёт `REPORT_FILE` инструмента 1.01
- слой-эталон `REFERENCE` у инструментов 1.05 и 1.06
- координаты Z и параметр `KEEP_Z` на объёмных данных
- запись в GeoPackage и подписи полей внутри файла
